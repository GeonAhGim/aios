# ADR-2026-09-04-B: 분석·전략작성·백테스트·마켓플레이스의 TradingView 수준 상향과 글로벌 데이터 커버리지 아키텍처

## Status
Accepted (2026-09-04, Chief Architect). 사용자 지시: "트레이딩뷰의 장점(차트/지표, 전략작성, 백테스트,
마켓플레이스)을 참조해 그 수준으로 올리고, 데이터 커버리지도 추후 그 수준이어야 하니 아키텍처에 반영".

## Context
- AIOS의 강점은 실행·리스크·회계·거버넌스(ADR-2026-09-03-B, L4 5종)이고, 약점은 사용자가 매일 만지는
  앞단이다: 차트는 기본 캔들 화면, 전략 작성은 조건 조합기(`cond-v2`), 백테스트는 봉 단위 단순 체결,
  마켓플레이스는 목록·구매·분쟁 골격, 데이터는 거래소 2곳.
- TradingView가 사실상의 기준을 만든 영역: (1) 차트·드로잉·레이아웃·리플레이, (2) Pine Script 같은
  시리즈 지향 스크립트 언어와 방대한 커뮤니티 스크립트, (3) 차트 위 즉시 백테스트와 Deep Backtesting,
  (4) 공개/보호/초대 스크립트 마켓과 평판, (5) 전 세계 거래소·브로커 데이터 커버리지.
- 이 다섯을 "리테일 편의"로 얕게 베끼면 06번 MVP 범위·103번 P0-first를 어긴다. 기관급으로 가져오려면
  각각을 **결정론·재현성·계보(lineage)·권한(entitlement)** 위에 얹어야 하며, 데이터 커버리지는 지금
  구조를 바꾸지 않으면 나중에 갈아엎게 된다.

## Decision
**D0. AIOS는 TradingView에 연결해 쓰는 보조 도구가 아니라, 차트·지표·전략작성·백테스트·마켓·데이터를 자체적으로 같은 수준으로 제공하는 독립 제품이다.** 외부 신호 수신(D6)은 선택 기능이며 우선순위 맨 마지막이다.

새 L4 명세 `docs/specs/L4_analytics_authoring_backtest_marketplace_v1.0.md`(리프 ID: DC·CH·IND·DSL·BT·MP·SIG)를
추가하고, 아래 원칙을 아키텍처에 고정한다.

### D1. 데이터 커버리지는 "공급자 SPI + 심볼 마스터 + 계층 저장소"로 지금 구조를 잡는다
- **심볼 마스터**: 전역 `instrument_id`(내부 ULID) ↔ 벤처별 심볼·ISIN/FIGI(있으면)·자산군·통화·틱사이즈·
  거래시간(캘린더)·생애주기. 모든 캔들·체결·포지션은 벤처 심볼이 아니라 `instrument_id`를 참조한다.
- **공급자 SPI(`MarketDataProvider` 포트)**: capabilities(자산군·타임프레임·히스토리 깊이·실시간 여부),
  rate-limit, entitlement(사용자/테넌트별 라이선스), 정규화 어댑터. 거래소 어댑터(Bitget·KIS/NH)는
  이 SPI의 첫 구현체로 재배치되고, 이후 데이터 벤더(예: Polygon·Databento·Kiwoom·EODHD — 미확인, §10)는
  어댑터 파일 하나로 추가된다.
- **계층 저장소**: hot(Postgres 파티션, 최근 N일·M1)·warm(Parquet/object store, 컬럼지향, ADR-2026-09-04-A의
  `CandleColumns`가 직접 읽음)·cold(아카이브). 파생 타임프레임은 M1에서 결정론적으로 집계하고 집계
  버전을 계보에 기록한다.
- **커버리지 레지스트리**: "어떤 벤처·자산군·기간이 어떤 품질로 있는가"를 질의 가능한 표로 유지해
  화면·백테스트가 사전에 알 수 있게 한다(없는 데이터를 조용히 0으로 채우지 않는다 — fail-closed).
- 규모 목표(설계 기준): 벤처 50, 종목 100k, M1 캔들 10억, 실시간 피크 50k msg/s, 5k봉 조회 p95 200ms.

### D2. 차트는 TradingView Lightweight Charts(Apache-2.0) 위에 AIOS 계층을 얹는다
- 차트 렌더링을 직접 만들지 않는다(자체 호스팅 오픈소스 라이브러리이며 TradingView 서비스·계정·API 의존은 없다). 캔버스 성능·시간축·시리즈는 라이브러리, AIOS는 데이터 스트림·
  지표 오버레이·드로잉 저장·레이아웃·리플레이·알림 생성·전략 신호 마커를 담당한다.
- 드로잉·레이아웃·워치리스트는 서버에 사용자/테넌트 스코프로 저장(버전·감사).
- 리플레이 모드는 백테스트 엔진과 같은 데이터 경로(컬럼지향)를 써서 "차트에서 본 것 = 백테스트가 본 것"을
  보장한다.

### D3. 전략 언어 "AIOS Script"는 Pine의 표현력을, 실행은 결정론 샌드박스를 택한다
- 시리즈 지향·정적 타입·순수 함수·I/O 없음·미래 참조 불가(컴파일 시 lookahead 검출)·리소스 상한.
- 컴파일 산출물(AST → IR)은 해시로 고정되고, 지표 레지스트리 버전·데이터 계보 해시와 함께 백테스트·실행·
  마켓 아티팩트의 재현 키가 된다.
- 기존 `cond-v2`는 AIOS Script의 부분집합으로 흡수한다(기존 전략은 자동 변환, 해시 보존 규칙 §3).
- 실행 엔진(`src/core/strategy/**`, FROZEN_PAPER_ONLY)은 건드리지 않고, 새 `src/core/script/**`가
  `condition_evaluator` 파사드로 붙는다. 파사드 접점 1개 파일만 ★(CA 승인) 대상으로 하며 이 ADR로 승인한다.

### D4. 백테스트는 "차트 즉시 백테스트"와 "딥 백테스트"를 같은 엔진으로 제공한다
- 즉시: 화면 범위·현재 TF, 초 단위 응답(컬럼 경로). 딥: 수십 년·M1 봉 확대(bar magnifier), 배치 잡.
- 현실성 모델을 계약으로 명시: 슬리피지(고정/비율/거래량 충격), 수수료 티어(벤처별), 지연, 부분체결,
  주문 유형(limit/stop/OCO/trailing), 펀딩·차입 비용, 기업행위 조정, 세션·휴장.
- 검증 파이프라인(기존 L4 strategy §3.5 과최적화 지표·워크포워드)은 그대로 위에 얹는다.

### D5. 마켓플레이스는 "보호 소스 + 검증된 사용 기반 평판 + 구독"으로 TradingView 대비 우위를 만든다
- 공개/보호(서버 실행만, 소스 비공개)/초대 전용/비공개 4단계. 버전·체인지로그·호환 데이터 범위 표기.
- 평판은 별점이 아니라 **검증된 사용 실적(PAPER 실행·백테스트 재현)** 가중. AST 유사도 해시로 표절 탐지.
- 일회 구매에 구독(정기 과금)·체험·수익배분 티어를 추가한다. 정산·환불·분쟁은 기존 원장 위에서.

### D6. 신호 유입(TradingView 웹훅 포함)은 실행이 아니라 "의도"로 받는다
- 사용자별 HMAC 시크릿·멱등키·재생 방지·스키마 검증·rate limit을 거쳐 `SignalIntent`로 정규화되고,
  기존 리스크 게이트(Master Authority)를 통과해야만 주문이 된다. 웹훅이 리스크를 우회할 길은 없다.

## Consequences
- 새 명세는 7개 하위영역 약 80 리프. 우선순위는 D1(DC, 구조 선행) → D2(차트)·지표 → D3(언어) → D4(백테스트) → D5(마켓) →
  D6(SIG, 선택 백로그). R(리스크)·L4(실행) 잔여 리프와 병행하되, D1은 R/L4보다 먼저 착수한다(나중에 바꾸면 비쌈).
- 프론트엔드 의존성 추가: `lightweight-charts`. 라이선스 Apache-2.0, 로고 표기 요구 준수(§10).
- 데이터 벤더 계약·라이선스는 사람이 결정한다. 명세는 어댑터 형태만 고정한다.

## Rejected
- 차트 엔진 자체 개발: 수년치 작업이며 차별점이 아니다.
- Pine Script 호환 실행기: 언어 사양이 비공개·비결정적 요소(repaint)가 있고, 호환을 약속하면 AIOS의
  결정론·감사 원칙을 지킬 수 없다. "가져오기 변환기"(부분 지원)는 후속 검토 항목으로 남긴다.
- 벤처 심볼 문자열을 그대로 키로 쓰는 현 구조 유지: 글로벌 커버리지에서 충돌·재상장·심볼 변경을 감당 못 한다.
