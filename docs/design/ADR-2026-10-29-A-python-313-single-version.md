# ADR-2026-10-29-A — Python 3.13 단일 지원 버전 전환

- 상태: Accepted (2026-10-29, 사용자 승인 "니가 권장하는대로")
- 출처: 3.10 전용 수정판 부재로 생긴 공급망 예외·적색 반복(dnspython, filelock 4.1.0 CVE 6건), 3.10 지원 종료 임박, 운영 이미지(3.11)와 CI(3.10)의 불일치
- 관련: ADR-2026-10-28-A(공급망 범프·예외 정책), ADR-2026-10-15-A(수렴 모드)

## 결정

1. 지원 버전을 **Python 3.13 하나**로 통일한다. 3.10·3.11은 단계적으로 폐기한다.
2. 3.13을 고른 근거(2026-10-29 실측): 현재 lock 111개가 패키지 변경 없이 3.13에서 설치된다(Windows·Linux 휠, `pip check` 통과). 3.14는 numpy·scipy를 올려야 해서 인터프리터와 수치 라이브러리 변경이 섞인다. 3.12는 지원 기간이 더 짧다.
3. **순서**(앞 단계가 끝나기 전에는 다음으로 가지 않는다):
   1. 정책: 이 ADR. 아무것도 삭제하지 않는다.
   2. 그림자 실행: 3.13 venv(`C:\aios\venv313`)로 비게이팅 테스트(`scripts/py313_shadow.py`)를 돌려 실패율·원인을 측정한다. 첫 full 녹색 직후 시작한다(3일 연속 녹색을 기다리지 않는다 — 전환 커밋이 카운터를 0으로 되돌린다).
   3. 앱 전환: 그림자 실행이 통과하면 `requires-python>=3.13`, Actions·Docker 3.13 통일, `tomli`·백포트 핀 제거, lock 공식 재생성.
   4. 엔진 전환: 함대 엔진(pm)과 로컬 CI 인터프리터를 3.13으로. pm 테스트를 3.13에서 먼저 통과시킨다.
   5. 폐기: 엔진·다른 프로젝트(smart_store 등)의 3.10 의존이 사라지고 안정 기간(1~2주)이 지난 뒤 3.10·3.11 venv와 인터프리터를 제거한다. 일찍 지우지 않는다(되돌릴 안전망).
4. 게이트·baseline·perf 예산은 전환을 이유로 완화하지 않는다. 3.13에서 달라지는 수치는 원인을 찾아 정정한다.

## 위험과 확인 항목

- `(str, Enum)`의 f-string/format 결과가 3.11부터 `값`에서 `클래스.멤버`로 바뀐다. 해시·서명·멱등키·DB 저장값에 닿으면 증적 체인과 replay_verify가 깨진다. 조사: `docs/design/PY313_PREP_enum_format.md`(전수), 후속 리프 20770(해시 입력 추적과 버전 독립 고정 테스트).
- 운영 이미지는 이미 3.11인데 지금까지 CI는 3.10이었다. 전환은 이 불일치를 해소한다.
- 일정 추정 1.5~3주(그림자 실행 실패율과 위 해시 확인 결과로 확정).

## 근거

- 3.13 휠 가용성 dry-run: 현재 lock 전부 설치 가능(Windows·manylinux), 3.14는 numpy 2.2.6·scipy 핀만 휠 없음
- `C:\aios\venv313`: Python 3.13.15, 111개 설치, `pip check` 통과, TA-Lib 포함 import 확인
- Actions `verify` 적색(2026-10-28): filelock 4.1.0 CVE 6건, 수정판 4.2.1은 Python>=3.11 전용 — 3.13 전환의 직접적 이득
