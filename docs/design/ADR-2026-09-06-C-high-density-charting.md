# ADR-2026-09-06-C: 고밀도 차트 — 한 화면에 수십 개 지표를 실사용 가능한 속도로

## Status
Accepted (2026-09-06, Chief Architect). 사용자 지적: "차트/지표에서 TradingView가 우위였던 부분, 특히 **한 차트에 굉장히 높은 밀도의
지표를 구성하는 것**이 반영됐는가."

## Context
- 기존 명세(CH-0~13, IND-1~14)는 **지표의 개수**(코어 100 + OSS 300 + 스크립트 무제한)와 **엔진 소유**는 해결했지만,
  **한 차트에 30~50개 지표를 동시에 얹고 팬·줌하는 사용 경험**은 다루지 않았다. 빠진 것이 구체적으로 넷이다.
  1. **멀티페인 관리**: 페인 추가·삭제·높이 조절, 페인별 독립 스케일, 크로스헤어 동기화.
  2. **계산 위치**: 지표 결과를 서버에서만 계산하면 지표 30개 × 팬/줌마다 왕복이 생겨 밀도가 올라갈수록 못 쓴다.
  3. **표시 계약**: 플롯 종류(선·히스토그램·영역·구름), 시리즈 간 채움(볼린저·일목구름), 스케일 바인딩(자체/오버레이/퍼센트/로그), 범례 값 표시.
  4. **밀도 운영**: 지표 템플릿(세트 저장·적용), 데이터 윈도우/객체 트리, 렌더 LOD·워커 분리.
- TradingView의 실제 우위는 지표 "개수"가 아니라 **이 네 가지의 완성도**다. 여기를 비우면 지표를 300개 넣어도 체감은 못 따라간다.

## Decision

### D1. 계산을 이중화한다 — 표시는 클라이언트 증분, 진실은 서버
- **표시용**: 브라우저에서 증분 계산(Web Worker + TS/WASM 엔진). 팬·줌·실시간 틱에 왕복 없음.
- **권위용**: 전략·백테스트·마켓 아티팩트가 쓰는 값은 **서버 계산만** 인정한다(재현 키·해시가 여기 붙는다).
- **동일성 강제**: 클라이언트 엔진은 서버와 같은 참조 벡터(IND-7/13)를 통과해야 한다. 불일치 지표는 클라이언트 계산을 끄고
  서버 값으로 폴백한다(무음 불일치 금지). 이것이 "빠르면서 신뢰할 수 있는" 유일한 구조다.
- 클라이언트 엔진 후보(라이선스 원문 확인 후 채택): `technicalindicators`(MIT, TS), TA-Lib WASM 빌드, 자체 포팅.
  코어 100종 중 표시 빈도 상위부터 이식하고 나머지는 서버 폴백.

### D2. 표시 계약(PlotSpec)을 지표 레지스트리의 1급 필드로 둔다
- 각 지표 출력은 `PlotSpec{kind: line|histogram|area|band|cloud|marker, scale: own|overlay|percent|log|inverted,
  fill_between: (out_a, out_b)|None, color_rule, precision, legend_format, default_pane}`를 갖는다.
- 서버·클라이언트·차트 엔진이 같은 스펙을 읽으므로 지표를 추가해도 화면 코드를 고치지 않는다(일목구름·볼린저 채움이 자동으로 그려짐).

### D3. 멀티페인·템플릿·데이터 윈도우를 정식 기능으로 명세한다
- 페인 CRUD·높이 비율·페인별 스케일·크로스헤어 동기화, 지표 순서·표시/숨김·잠금.
- **지표 템플릿**: 지표 세트 + 설정 + 페인 배치를 저장해 어떤 종목에도 적용, 마켓플레이스 공유 대상(MP 규칙 재사용).
- **데이터 윈도우**: 크로스헤어 시점의 모든 지표 값을 한 패널에 표시(밀도가 올라갈수록 필수).

### D4. 밀도 성능 목표를 SLO로 못박는다
- **지표 30종 × 10만 봉에서 팬/줌 p95 프레임타임 ≤ 16.7ms**, 지표 추가 반영 ≤ 100ms, 실시간 틱 갱신 ≤ 8ms.
- 수단: 렌더 레이어 분리(캔들/오버레이/드로잉/커서), 뷰포트 밖 계산 생략, 줌아웃 시 LOD 다운샘플링(LTTB류, 극값 보존),
  Web Worker 계산, 오프스크린 캔버스.
- CH-0 벤치 스크립트를 **지표 밀도 벤치**로 확장해 회귀를 CI에서 잡는다.

## Consequences
- 확장 리프 CH-14~19, IND-15~16 (분석 명세 §9.11). MVP-1 포함, 약 +8 리프.
- CH-1(KLineChart 포크 반입)은 그대로 유효하다 — KLineChart는 멀티페인·오버레이 확장을 이미 갖고 있어 D3의 토대가 된다.
- 클라이언트 계산 도입으로 "화면 값과 백테스트 값이 다르다"는 고전적 사고 위험이 생기므로, D1의 동일성 강제와 폴백이 필수 조건이다.

## Rejected
- 서버 계산만 유지: 밀도가 올라가면 왕복 비용으로 사용 불가.
- 클라이언트 계산만 유지: 재현·감사 불가, 전략 값과 화면 값이 갈라진다.
- Highcharts Stock·AnyChart 등 상용 차트: 라이선스 비용과 소유권 원칙(ADR-2026-09-04-B D2) 위배.
