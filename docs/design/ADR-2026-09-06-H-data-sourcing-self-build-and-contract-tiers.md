# ADR-2026-09-06-H: 데이터 조달 — 자체 구축 범위, 계약 등급 교체 가능성, 재배포 스코프

## Status
Accepted (2026-09-06, Chief Architect). 사용자 지시: "가입만 하면 되는 건 하겠다. 나중에 상용화했을 때
기업용 가입이 되어야 할 경우도 있으니 뗐다 붙였다 할 수 있게 해야 할 것 같다. 유료 부분은 나중에 직접 구축하는 게 어떨까."

## Context
ADR-2026-09-06-A가 소스를 3계층(무료 즉시 / 유료 후속 / 금지)으로 나눴지만, 두 가지를 결정하지 않았다.
(1) 같은 소스의 **계약 등급이 바뀔 때**(개인 → 기업 → 재배포 허용) 코드가 안 바뀌는가.
(2) 유료 항목 중 무엇이 **자체 구축으로 대체 가능**하고 무엇이 불가능한가.

저장소 실측: `entitlements` 테이블(`9049e2b6b0b7:100`)과 `EntitlementPort`(`ports/entitlement.py`)가 이미 있고
**fail-closed**로 동작한다(정보 결손은 거부). 자격증명은 `exchange_credentials` + `secret_ref`/`secret_handle`로
키링화돼 있다. 없는 것은 **계약 등급**과 **재배포 스코프**다 — `entitlements`는 "이 테넌트가 이 벤처를 볼 수
있는가"만 알고, "우리가 이 데이터를 남에게 보여줘도 되는가"는 모른다.

## 핵심 구분
**"만들 수 있느냐"와 "보여줄 권리가 있느냐"는 다른 문제다.**
데이터를 직접 수집해도 재배포 권리가 생기지 않고, 재배포 권리를 사도 과거 데이터가 생기지 않는다.
이 둘을 섞으면 "직접 구축하면 유료 계약이 필요 없다"는 잘못된 결론에 이른다.

## Decision

### D1. `source_contract`를 신설하고 등급을 행으로 교체한다 (신규 컨텍스트 아님)
기존 `entitlements`·`connections`·키링을 **확장**한다. 새 컨텍스트를 만들지 않는다(ADR-G §3 원칙).

| 필드 | 값 | 의미 |
|---|---|---|
| `source_id` | `OPENDART`·`ECOS`·`KRX`·`BINANCE`·`EODHD`… | 소스 식별 |
| `tier` | `FREE` / `PERSONAL` / `BUSINESS` / `ENTERPRISE` | 계약 등급 |
| `credential_ref` | 키링 핸들 | 실제 키는 여기 없다 |
| `redistribution_scope` | `NONE` / `INTERNAL` / `DISPLAY` / `REDISTRIBUTE` | **아래 D2가 강제** |
| `rate_limit`·`quota` | 정수 | 등급마다 다르다 |
| `valid_from`·`valid_to` | 시각 | 계약 기간. 만료는 fail-closed |

**등급 승격은 행 갱신이다.** 개인 키로 개발하다가 기업 계약으로 바꿀 때 코드·배포가 바뀌지 않는다.
어댑터는 `source_id`만 알고 등급을 모른다 — 등급은 호출 전 게이트가 읽는다.

### D2. 재배포 스코프를 코드 경로가 강제한다 (선언만으로 두지 않는다)
`INTERNAL`은 내부 계산에만 쓸 수 있고 화면에 못 띄운다. `DISPLAY`는 우리 사용자에게 보여줄 수 있으나
내보내기·API 재판매가 안 된다. `REDISTRIBUTE`만 외부 제공이 가능하다.
강제 지점은 셋이다 — 읽기 API(`application/read_api.py`), 차트·백테스트 경로, 내보내기·리포트.
**미지정은 `NONE`으로 취급한다**(기존 entitlement와 같은 fail-closed 규율).

이것이 없으면 나중에 "이 화면이 어느 계약으로 뜨는 데이터인가"를 코드 전수조사로 답해야 한다. 지금은 컬럼 하나다.

### D3. 자체 구축한다 — 벤더보다 낫거나 같은 것
| 대상 | 판단 | 근거 |
|---|---|---|
| **암호화폐 틱·호가(L2)** | **자체 수집** | Binance·Bybit·OKX·Upbit 공개 WebSocket이 전체 호가 깊이를 무료로 준다. 이 영역에서 Databento는 필요 없다 |
| **국내 기업행위**(분할·합병·배당) | **자체 구축** | 전자공시가 **1차 발행자**다. 벤더는 이걸 재판매한다. 원본에서 뽑는 편이 정확도·정정 추적 모두 낫다 |
| **거래소 캘린더·세션** | **자체 구축** | 거래소가 휴장일을 공시한다. 연 1회 갱신 작업이다. 현재 `source: UNVERIFIED` 자리표시자를 이걸로 해소한다 |

### D4. 자체 구축이 불가능한 것 — 정직하게 못 박는다
| 대상 | 왜 불가능한가 |
|---|---|
| 미국 주식·옵션 틱·호가 | 데이터가 **발생 지점에서 라이선스된다**. 수집 수단이 없다 |
| 차입 가능 수량(locate) | 브로커 계좌에 딸린 정보다. 데이터 구매가 아니라 계좌 개설이다 |
| **실시간 시세 재배포 권리** | 법적 문제이지 기술 문제가 아니다. 직접 수집한 데이터라도 국내 실시간 시세를 상용 화면에 띄우려면 거래소·정보사업자 계약이 필요하다 |
| 해외 광범위 기업행위 | 국내는 전자공시로 되지만 전 세계는 소스가 흩어져 있다. 장기 꼬리는 구매가 싸다 |

### D5. 기록은 소급되지 않는다 — 수집을 지금 시작한다
**벤더가 파는 진짜 상품은 과거다.** 직접 수집은 시작한 날부터만 쌓인다.
암호화폐 L2 수집을 **지금 시작**한다. 지금 안 쓰더라도, 오늘 기록하지 않은 하루는 나중에 돈으로도 못 사는 경우가 있다.
비용은 라이선스가 아니라 **저장·운영**이다(심볼 소수라도 일 단위 GB). 보존 정책을 처음부터 넣는다:
전체 깊이는 단기 보존, 집계·상위 N호가는 장기 보존.

### D6. 유료 어댑터는 계약 없이도 지금 형태를 고정한다
`ingest_source.py` 포트 뒤에 어댑터를 두되, **계약 전에는 등록하지 않는다**(빈 어댑터 금지).
대신 소스별 능력 기술(`capability`: 자산군·해상도·기업행위 유무·재배포 가능 등급)을 `source_contract`에 넣어,
계약 시점에 행 하나로 붙는 상태를 만든다.

## Consequences
- 신설 리프 5개, 약 1,450줄.
- 무료 키 5종만으로 리서치 데이터 리프가 열린다. 유료 계약은 **실제로 없는 과거 데이터가 필요해질 때**로 미룬다.
- 상용화 시 필요한 것은 코드 변경이 아니라 계약 행 갱신 + 재배포 스코프 승격이다.
- 암호화폐 정밀 데이터에서는 유료 벤더가 **영구히 불필요**해질 수 있다. 미국 주식·옵션에서는 대체 불가다.

## Rejected
- **"직접 구축하면 유료 계약이 전부 불필요"**: 재배포 권리와 미국 시장 데이터는 기술로 대체되지 않는다.
  자체 구축은 비용을 줄이지 규제를 없애지 않는다.
- **등급을 환경변수·배포 분기로 처리**: 개인/기업 배포가 갈라지면 두 벌을 유지하게 된다. 행 하나로 끝낼 일이다.
- **재배포 스코프를 문서로만 관리**: ADR-G가 확인한 실패 양식 그대로다. 선언은 강제되지 않으면 없는 것과 같다.
- **계약 전 유료 어댑터 선작성**: 스키마·인증이 계약 등급마다 다르다. 추측으로 쓰면 계약 후 다시 쓴다.
