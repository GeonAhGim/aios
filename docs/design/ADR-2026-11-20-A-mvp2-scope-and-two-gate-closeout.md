# ADR-2026-11-20-A: MVP-2 범위 확정과 두 관문(T2/U2) — 내장 전략 엔진은 MVP-3으로

## Status
Accepted (2026-11-20, 사용자 승인: "모두 승인. 내장 전략 엔진은 MVP-2 이후로 하자"). MVP-1 종결(ADR-2026-11-18-A 관문 T/U)은 그대로 둔다.

## Context

- MVP-1은 J1~J3(가입·온보딩, 종목 발견·백테스트, 모의 주문)다. 이것만으로는 쓸 만한 제품이 아니다. 감시·복구(J4), 리서치·리포트(J5), 설정·승인·감사(J6)는 ADR-2026-09-24-A Decision 4가 이미 MVP-2로 정했다(`docs/specs/UX_JOURNEYS.md` §1).
- ADR-2026-11-18-B(글로벌 규모 프런트엔드 프로그램)는 Phase 0(문서 전용), Phase 1(MVP-2 UI 단계)로 나눈다. 명세가 구현보다 먼저다(원칙 1).
- ADR-2026-09-29-A(내장 전략 지능 엔진, Proposed)는 이 엔진을 "MVP-2 첫 명세"로 정했다. 범위가 매우 커서(분석·생성·고도화·자가학습, 증권·가상자산 이원화, 사이드카 서비스) MVP-2에 넣으면 "기본적으로 쓸 수 있는 제품"의 완료가 멀어진다.
- 종결 대기 동안 명세 처리 능력이 비고, 문서 전용 작업은 MVP-1 종결 지표(재오픈·자기조치)에 영향이 없다.

## Decision

### D1. MVP-2 범위 ("기본적으로 사용 가능한 제품", PAPER 기준)

포함:
- 여정 J4(감시·복구), J5(리서치·리포트), J6(설정·승인·감사)와 U-1~U-14(범용 과업) 중 이 여정에 매핑된 것(UX_JOURNEYS §3).
- 프런트엔드 Phase 1의 필수 항목: 횡단 규칙집(FE-2) 구현, 최소 디자인 토큰(FE-3), 한국어·영어(FE-4), 접근성 핵심(FE-5), 실스택 e2e·계약 테스트(FE-8), 성능 단언 전환(단일 표본 제거).
- 보안 프로그램 S1(갭 해소 구현, `docs/security/SECURITY_PROGRAM.md`). 사용자 팀 모의해킹은 패키징 전에 본격 수행한다.
- 패키징·배포 준비(compose.prod, 모니터링, 롤백).

MVP-3으로 이동(이 ADR이 이전 문서보다 우선한다):
- **내장 전략 지능 엔진**(ADR-2026-09-29-A). 그 ADR의 내용·불변식은 그대로이고 일정만 MVP-3이다. "MVP-2 첫 명세" 문구는 이 ADR로 대체된다.
- 작업 공간 FE-9(Pro Workspace), 외부 플러그인(스트리밍·제휴·방송·보안·DevEngine), 모바일 앱, 다국어 확장.
- LIVE(실거래) 전환: MVP-2 뒤 별도 관문(HB-5 하드 가드, 사용자 팀 모의해킹 결과, 사용자 서명).

### D2. 순서: 명세(문서)는 지금, 구현은 MVP-1 기술 종결 뒤

- 화면 명세·여정 보강·설계 문서는 **지금 시작**한다(문서 전용, ADR-2026-11-18-B Phase 0 연장).
- MVP-2 **구현 리프**는 MVP-1 관문 T 통과(`docs/milestones/MVP-1_CLOSEOUT.md` 생성) 뒤에 푼다. 기존 보류 해제 규칙(종결 파일이 있어야 hold 해제)을 그대로 쓴다.
- 이유: 구현 리프는 CI 변동으로 재오픈·자기조치 시계를 되돌릴 수 있다. 문서는 그렇지 않다(단, 문서를 읽는 게이트는 `docs/frontend/README.md`의 체크리스트를 따른다).

### D3. MVP-2도 같은 두 관문

- **관문 T2(기술)**: 기계 지표. MVP-1 관문 T와 같은 지표 체계(연속 녹색, 재오픈 0(원인 기준, ADR-2026-11-19-A), 자기조치 서명 ≤8/일)에 MVP-2 항목을 더한다: J4~J6 실스택 e2e 녹색, 보안 S1 갭 0, 단일 표본 성능 단언 기준선 0, 화면 명세 갭 표의 "차단" 항목 0. 통과 시 태그 `milestone/MVP-2-tech`, `docs/milestones/MVP-2_CLOSEOUT.md`.
- **관문 U2(사용자)**: 사용자가 UAT 스택에서 J4~J6를 직접 수행하고 `docs/milestones/MVP-2_USER_SIGNOFF.md`에 서명한다. 서명 전에는 에이전트가 이 파일을 쓰지 않는다. 통과 시 태그 `milestone/MVP-2`.
- 항목 정의의 세부(closeout_check에 들어갈 정확한 항)는 MVP-2 구현이 시작되는 시점에 ADR 개정으로 확정한다. 항목은 **기계가 판정할 수 있는 것만** 넣는다.

### D4. 공개 서비스 개시 조건 (사용자 확인 2026-11-20 — ADR-2026-09-29-A §9 대체)

내장 엔진 구현은 수개월 규모라서 개시 조건으로 걸지 않는다. **공개 서비스 개시는 MVP-2 뒤**(기술 관문 T2, 사용자 관문 U2, 패키징 전 사용자 팀 모의해킹 통과)이고 내장 엔진은 개시 조건이 아니다.
- 엔진 없이도 제품이 비지 않는다: 사용자가 만든 전략과 **외부 전문 엔진의 제안**(MCP `submit_proposal` 채널, ADR-2026-09-29-A §4)이 기존 검증·컴플라이언스·모의 실행 파이프라인을 그대로 탄다.
- 내장 엔진(MVP-3)은 같은 채널로 **개시 뒤에 얹는 업그레이드**다. 불변식(S-tier 무변경, 미래 참조 금지, 과최적화 방지)은 ADR-2026-09-29-A 그대로다.
- 개시 범위는 PAPER다. LIVE(실거래) 전환은 별도 관문으로 그 뒤에 둔다(HB-5 하드 가드, 모의해킹 결과, 사용자 서명).
- ADR-2026-09-29-A §9의 "공개 서비스 개시는 특화 엔진이 엔터프라이즈급으로 완료된 뒤" 문구는 이 항으로 대체된다.

## Consequences

- MVP-2는 "쓸 수 있는 제품"에 집중하고, 규모가 큰 엔진·작업 공간·플러그인이 완료를 늦추지 않는다.
- 명세 파이프라인(`docs/frontend/spec_manifest.json`, 발행기)을 J4~J6 화면까지 넓힌다. 종결 지표와 무관한 문서 전용 작업이다.
- 위험: MVP-2 범위가 다시 커질 수 있다 — 범위 추가는 이 ADR 개정으로만 한다. 엔진 없이 개시하므로 초기 전략 공급은 사용자 전략과 외부 엔진 제안에 의존한다(외부 엔진 연결 계약과 제안 품질 심사는 MVP-2 안에서 점검한다).

## Rollback

이 ADR을 Superseded로 두고 ADR-2026-09-29-A의 "MVP-2 첫 명세" 문구를 복원한다.
