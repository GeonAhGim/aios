# ADR-2026-09-29-A: MVP-2 내장 전략 지능 엔진(분석·생성·고도화·자가학습) — 무료 벤더만, 가상자산 우선 프로덕션 수준

## Status
Proposed (2026-09-29, Chief Architect). 사용자 지시 2026-09-29 23:20 + 2026-09-30 00:40(사이드카 아키텍처·증권/가상자산 이원화·사용 누적 학습 자산화) 반영. **착수 시점은 ADR-2026-09-26-C 종결 지표 충족 후** — 그 전에는 명세 리프를 발행하지 않는다.

## Context (실측 2026-09-29)
- AIOS의 AI 계층(AI-1~22 done)은 "제안 폼(`ProposalDraft`) → 컴파일 → 백테스트 검증 → 확인 토큰 → 페이퍼" 파이프라인이며, 전략을 **분석·생성하는 두뇌는 외부**(Anthropic/OpenAI/Gemini/로컬 LLM 공급자 또는 MCP 에이전트)다. 자체 분석 로직은 없다.
- 리서치 데이터 플레인(RD-1~18 done)은 거시(FRED·ECOS·KOSIS)·공시(DART·EDGAR)·뉴스(GDELT·RSS)를 point-in-time으로 저장하지만 DSL에서는 `research.*_count()` 개수만 참조 가능하고 해석 계층(레짐·팩터·이벤트 태깅)이 없다. 원자재 소스는 없다.
- 기술지표(TA-Lib 전 지표·OSS·스크립트 계층), 벡터화 백테스트·워크포워드, 실험 계보, ML 피처스토어·드리프트는 갖춰져 있다.
- 사용자 판단: 재료가 원시 수준이면 거시·미시 기반 전략에는 사실상 무의미하다. 증권용·가상자산용 **외부 전문 엔진**을 별도 개발해 나중에 연결할 계획이지만, 그와 별개로 **내장 엔진은 필요**하다.

## Decision
1. **범위**: MVP-2에 "내장 전략 지능 엔진"을 넣는다. 책임 4가지 — (a) 분석: 시장·거시·온체인·파생 데이터에서 레짐·팩터·이벤트 피처 생성, (b) 생성: 피처·가설 템플릿에서 `ProposalDraft`를 자체 생성(외부 LLM 없이도 동작, LLM은 선택적 보강), (c) 고도화: 파라미터 스윕·워크포워드·앙상블·리스크 조정으로 기존 전략 개선 제안, (d) 자가발전·학습: 실험 계보(AI-10/11)와 페이퍼 결과를 학습 데이터로 삼아 다음 세대 제안을 만드는 루프(드리프트·과최적화 게이트 포함).
2. **완성 기준**: 엔터프라이즈급이 아니어도 **프로덕션 수준** — 가상자산(현물·무기한선물, OKX 등 기존 어댑터 범위)만이라도 24×7 무인 운영, 장애 시 안전 정지, 재현 가능(실험 계보·프롬프트 해시·데이터 as_of), 페이퍼에서 실측 지표(샤프·MDD·회전율·슬리피지 반영)로 승격 판정. 증권은 데이터 계약만 맞추고 2차.
3. **데이터 벤더는 무료만**: 유료 벤더 도입 없음. 후보(각각 이용약관·재배포 조건을 RD-1 방식으로 원문 인용 후 채택): 거시 FRED·ECOS·KOSIS(기존), 원자재·환율·지수 — FRED 원자재 시계열·Stooq·Yahoo Finance 비공식(약관 검토 필수, 불가 시 제외), 가상자산 — 거래소 공개 API(OKX/Binance/Bybit 캔들·펀딩·OI·청산), 온체인 — 공개 노드/무료 티어(Blockchain.com·mempool.space·DefiLlama), 심리 — Alternative.me Fear&Greed, 뉴스 — GDELT·RSS(기존). 약관상 저장 불가 소스는 link_only/파생 피처만 저장.
4. **외부 전문 엔진과의 관계**: 증권용·가상자산용 외부 엔진은 기존 MCP `submit_proposal`(AI-16) 채널로 연결한다. 내장 엔진도 **같은 폼·같은 검증 파이프라인**을 탄다(내장이라고 우회 없음, I-12 AI/LIVE 분리 유지). 내장 엔진의 분석 피처는 외부 엔진도 read/research 도구로 읽을 수 있게 노출한다.
5. **불변식**: S-tier(주문·자금) 경로 무변경; 학습 데이터에 Claude/Codex 출력 미사용(기존 규칙); 미래 참조 금지(RD-9 as_of 바인딩 전 구간 적용); 과최적화 게이트(워크포워드 OOS 없이는 승격 불가); 자가학습 루프는 페이퍼까지만 자동, LIVE는 사람 확인 토큰.
6. **아키텍처(사용자·Gemini 검토 2026-09-30 반영)**: 엔진은 AIOS 프로세스 밖의 **격리된 사이드카 서비스**(감독자 재기동, 장애 시 AIOS에 "제안 중단" 플래그만 전달)이며, 기존 포트에 꽂힌다 — MCP `submit_proposal` 채널(제안) + 피처 조회 API 1개(HTTP/gRPC) + Arrow 포맷 데이터. 밀리초 경로(주문·리스크 게이트·서킷브레이커·킬스위치)는 기존 AIOS 결정론 코드가 담당하고 엔진·LLM은 개입하지 않는다(I-12, S-tier 로컬 LLM 금지). 엔진 장애 시 안전 모드 = 신규 제안 중단 + 기존 리스크 게이트 유지. 하드웨어 전제 없음(로컬 27B 기본, 클라우드 API 선택 보강). "커널-드라이버" 비유는 쓰되 AIOS 재설계는 하지 않는다(안정화 단계와 충돌).
7. **이원화**: 내장 엔진도 **증권용(`securities`)과 가상자산용(`crypto`)** 두 특화 엔진으로 나눈다. 공통 코어(피처 계약·제안 생성기 골격·학습 루프·평가 게이트)는 한 패키지, 시장 특화(데이터 소스·거래시간·호가단위·규제·파생 구조)는 엔진별 패키지. 순서는 crypto 먼저 프로덕션, securities는 데이터 계약·KIS/키움/NH 어댑터 위에 2차. 외부 전문 엔진도 같은 두 슬롯에 같은 규격으로 연결한다.
8. **사용 누적 학습 = 회사 자산(사용자 지시 2026-09-30)**: 엔진은 사용될수록 우리 서버에 학습이 쌓여야 한다. (a) 제안·평가·백테스트·페이퍼·(승인 시)실거래 결과와 사용자 채택/폐기 신호를 실험 원장(AI-10/11 WORM·계보)에 구조화 기록 — 이것이 학습 피드. (b) 학습 대상은 "가설→결과" 쌍·피처 유효성·레짐별 성과·전략 라이브러리이며 대화 원문이 아니다. (c) 모델·피처스토어는 우리 소유(AI-18~21 로컬 학습 파이프라인 기반), 외부 API는 보강일 뿐 핵심 지식은 외부에 남기지 않는다. (d) 테넌트 분리·동의: 공용 학습은 약관 옵트인·익명화 후에만, 개별 사용자 전략 원문은 그 사용자 자산으로 격리(SRC IR-only). (e) 외부 LLM API 출력의 재학습 가능 여부는 벤더 약관별로 확인해 문서화. 목표: 프로덕션급에서 출발해 누적 학습으로 엔터프라이즈급을 넘어서는 단계까지 — 지금의 경량·무료 벤더 제약은 출발 조건이지 상한이 아니다.
9. **서비스 개시 조건·규모(사용자 지시 2026-09-30 00:55)**: 공개 서비스 개시는 **특화 엔진(증권·가상자산 둘 다)이 엔터프라이즈급으로 완료된 뒤**. 그 전까지는 **최대 5개 계정**(계정당 증권+가상자산 서비스 1식), 부하가 크면 3개까지 축소. 따라서 MVP-2 기간의 용량 설계 기준은 5 계정 × 2 시장이며, 다수 사용자용 GPU 서버·1~2초 응답 SLO는 개시 전 단계로 미룬다. **LLM 모델 평가는 후순위** — Qwen3 계열(Apache-2.0)을 기본 가정으로 두고 어댑터(AI-7 openai_compatible_provider) 뒤에서 교체 가능하게만 유지, 벤더 평가 문서는 개시 전 단계에서 작성.
10. **착수 순서(명세는 안정화 종결 후 발행)**: ① 무료 벤더 평가 문서(RD-1 형식) ② 가상자산 시장·파생·온체인 수집 어댑터 ③ 피처/레짐 엔진 ④ 제안 생성기(템플릿 기반) ⑤ 고도화(스윕·앙상블) ⑥ 자가학습 루프·게이트·학습 피드(원장→피처스토어) ⑦ 24×7 운영·감시 패널 ⑧ securities 엔진(공통 코어 재사용). 각 단계는 L4 명세 1편(≤300줄 파일 원칙, 리프 ≤500줄)로 발행.
