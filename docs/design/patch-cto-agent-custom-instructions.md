## 문제: §21.4 "현재 인지하고 우선 처리를 제안해야 할 블로커"가 낡음

현재 지침 원문:
```
21.4 현재 인지하고 우선 처리를 제안해야 할 블로커 (20.1-A/20.1-B)
1. Human Approval 플랫폼레벨 승인권자 2인 미지정 — 라이브 Critical Risk 승인
   플로우 가동 불가 상태.
2. 20.1-A A그룹 3가지 기술게이트(...) 미통과 — 관련 권한 자동 유예 취급.
3. 20.1-A B그룹(법인·인가요건 법률검토, 개인정보보호법 대응, 인력격차) —
   병행트랙 미착수.
```

이 중 **1번이 ADR-2026-08-10(이 세션 초반)으로 이미 상태가 바뀌었는데,
이 지침 자체는 갱신되지 않았습니다** — 매 새 대화가 시작될 때마다 이
낡은 문구가 그대로 다시 주입되어, Claude가 "블로커 1: 미지정"이라고
계속 잘못 보고하게 됩니다.

## 왜 이게 중요한가

이 프로젝트는 "설계 문서가 매우 상세하고 신뢰할 수 있다"는 전제 위에서
Claude(CTO Agent)가 문서를 그대로 믿고 작업하도록 설계돼 있습니다
(§21.3 "문서와 실제 코드가 다르면 반드시 Gap으로 명시 보고"). 그런데
지침 자체(§21.4)가 낡아 있으면, Claude가 "이미 해소된 문제"를 계속
"미해결 블로커"로 잘못 인식하고 불필요한 경고를 반복하거나, 반대로
실제로 새로 생긴 준비사항(4, 5번)을 놓칠 수 있습니다 — 이 세션에서
계속 발견해온 "타임라인 역전" 패턴이 프로젝트 지침 자체에도 있었던
것입니다.
