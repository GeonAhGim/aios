# ADR-2026-09-06-D: 제품 경험·발견 기능 — 경쟁 우위 확보와 UX 리팩터링 차단

## Status
Accepted (2026-09-06, Chief Architect). 사용자 지시: "기능들과 사용자 경험 측면에서 타 제품군 대비 비교우위에 있도록 확장할 것들을 확인하라."

## Context
지금까지의 12개 L4 명세는 **엔진·통제·데이터**를 T1+ 수준으로 올렸지만, 사용자가 매일 만지는 **발견(discovery)·의사결정 보조·플랫폼 UX**는
경쟁 제품 대비 빈 칸이 남아 있다. 실측 점검 결과 두 종류의 문제가 있다.

**(가) 지금 안 하면 대규모 재작업이 되는 것**
- **다국어 부재**: `frontend/apps/web/src`의 `.tsx` 149개 중 **147개에 한국어 문자열이 하드코딩**돼 있고 i18n 프레임워크가 없다
  (`index.html`은 `lang="en"`). 화면이 60개를 넘어간 뒤 도입하면 전 파일 재작성이다.
- **디자인 시스템·접근성 기준 부재**: `packages/ui-web`는 있으나 토큰·접근성 계약이 없어 화면마다 제각각이 된다.
- **결정 이력(decision trail) 필드 부재**: 지금 FA-13(이벤트 스토어)이 만들어지는 중이라 `causation_id`/`correlation_id`에
  UX가 필요한 연결 정보를 지금 넣지 않으면 나중에 이벤트를 재마이그레이션해야 한다.

**(나) 경쟁 제품에 있고 우리에겐 없는 것** — TradingView/Finviz(스크리너), 3Commas(팔로우 트레이딩), QuantConnect(리서치 노트북),
Aladdin/CRD(사전 영향 분석·리밸런싱 워크플로), 공통(모바일·알림 센터·명령 팔레트·온보딩).

## Decision

### D1. 다국어를 지금 넣는다 (UX-1~2, 최우선)
- 프레임워크 도입 + **기존 147개 파일의 문자열 키 추출**을 기계적 변환으로 한 번에 처리한다. 기본 로케일 `ko`, 동시 지원 `en`.
- 규칙: 사용자 노출 문자열은 코드에 리터럴로 두지 않는다(ESLint 규칙 + CI 검사로 강제). 에러 코드 → 문구 매핑은 이미 한 곳에 모여
  있으므로(`components/ErrorMessage.tsx`) 그 구조를 로케일 사전으로 승격한다. 숫자·통화·날짜는 로케일 포매터 사용.
- **금액·수량은 절대 로케일 반올림을 타지 않는다**(Decimal 문자열 유지) — 금융 제품에서 흔한 사고를 규칙으로 차단.

### D2. 디자인 시스템·접근성을 계약으로 만든다 (UX-3~4)
- 디자인 토큰(색·간격·타이포·상태), 공용 컴포넌트 계약, 다크 모드. 접근성은 **키보드 전 경로 도달·포커스 표시·대비 4.5:1·
  스크린리더 레이블**을 CI(axe류)로 검사한다. 지금 기준을 세우면 이후 화면은 자동으로 따라온다.

### D3. 발견 기능 — 스크리너를 우리 강점 위에 만든다 (UX-5~8)
- 지표·펀더멘털·공시·백테스트 통계를 **한 쿼리로** 거르는 스크리너. 경쟁 제품은 지표나 펀더멘털 중 하나만 되지만,
  AIOS는 지표 레지스트리 + 리서치 데이터 + 실험 원장을 이미 갖고 있어 **"RSI<30 이면서 최근 공시에 유상증자 없고 이 전략의
  백테스트 승률 상위" 같은 교차 조건**이 가능하다. 이것이 발견 영역의 비교우위다.
- 결과에서 바로 차트·백테스트·전략 적용으로 이어지고, 스크린 조건은 저장·공유(마켓 규칙 재사용)·알림 등록이 된다.

### D4. 의사결정 보조 — 사전 영향 분석과 리밸런싱 (UX-9~12)
- **What-if 사전 영향**: 주문을 내기 전에 그 주문이 포지션·노출·VaR·한도·컴플라이언스에 미치는 영향을 미리 보여준다.
  리스크 엔진과 포트폴리오 엔진이 이미 있으므로 **읽기 전용 평가 경로**만 추가하면 된다(주문 생성 없음).
  기관 제품의 핵심 기능이며 리테일 제품에는 사실상 없다.
- **리밸런싱 워크플로**: 목표 비중 → 이탈 계산 → 주문 초안 생성 → 승인 → 실행. `core/portfolio`의 리밸런스 로직을 화면과 연결한다.

### D5. 커뮤니티·팔로우 — 마켓플레이스의 두 번째 형태 (UX-13~15)
- 전략 **구매**와 별개로 **팔로우**(다른 사용자의 PAPER 실행 신호를 내 페이퍼 계좌에 복제)를 지원한다. 리테일 제품의 최대 유입 경로다.
- 안전장치: 팔로우도 내 리스크·컴플라이언스 게이트를 통과해야 하며, 비중은 팔로워가 정한다(원본 계좌 규모와 무관).
  **투자자문으로 오인될 표현을 UI에서 금지**하고, LIVE 개통 전까지는 PAPER 전용이다.

### D6. 플랫폼 UX (UX-16~22)
- **모바일**: PWA(설치·오프라인 셸·푸시). 푸시 백엔드(`device_tokens`)는 이미 있다. 네이티브 앱은 하지 않는다.
- **알림 센터·다이제스트**: 알림 이력 한 곳, 일간 요약(이메일·푸시), 알림 규칙 관리.
- **명령 팔레트·단축키**: 종목·화면·액션을 키보드로. TradingView 사용자가 기대하는 파워유저 UX.
- **온보딩·빈 상태**: 첫 실행 가이드(거래소 연결 → 전략 → 페이퍼 실행), 모든 목록 화면의 빈 상태 문구·다음 행동.
- **결정 이력 뷰어**: "왜 이 주문이 막혔나 / 왜 이 값이 나왔나"를 이벤트·판정·데이터 계보로 거슬러 보여준다.
  T1 제품이 가장 약한 지점이고, 우리는 이벤트 소싱·재현·해시 계보를 이미 만들고 있으므로 **거의 공짜로 얻는 차별점**이다.

## Consequences
- 새 명세 `L4_product_experience_and_discovery_v1.0.md`(UX-1~22). MVP-1 포함, +22 리프(총 약 344).
- **UX-1~4는 다른 프론트 리프보다 먼저** 배정한다(다국어·디자인 토큰·접근성·결정이력 필드). 지금이 최저 비용 시점이다.
- FA-13(진행 중)의 이벤트 계약에 `causation_id`·`correlation_id`·`actor`·`decision_refs`가 포함돼야 UX-22가 성립한다 — 이 ADR로 요구사항을 고정한다.

## Rejected
- 네이티브 모바일 앱: 유지비 대비 이득이 낮고 PWA로 충분하다.
- 소셜 피드·채팅: 운영·규제 부담이 크고 제품 정체성(운용 통제)과 멀다. 팔로우 기능으로 대체한다.
- LIVE 상태의 카피 트레이딩: 투자자문·일임 규제 영역. MVP-1 범위 밖이며 별도 법률 검토 후 결정한다.
