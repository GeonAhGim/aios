# ADR-2026-09-08-A: 대리 기간 거버넌스 추인과 운영 결정 6건

## Status
Accepted (2026-09-08, Chief Architect). 사용자 지시: "프로젝트의 성공과 완성도 높은 구현을 위해 전권을 가지고
진행하라. GitHub 유료 플랜 결제해 놓았다." 직전에 별도 세션(내부 감사 역할)이 Fable 부재 기간(9/3 저녁~9/8)의
대리(Opus) 작업을 읽기 전용으로 점검해 사람 결정 항목 7건을 남겼다. 이 ADR은 그 7건을 닫는다.

## Context
점검 보고의 한 줄 판정: "산출물은 원 설계와 정합하고 P0 안전 결함은 실제로 종결됐다. 다만 속도의 비용이
조정 실패(함대 전면 정지 2회, 겹침 태스크 6쌍)로 나타났다." 보고 자체는 정확했고, 한 가지만 정정한다 —
"최신 로컬 CI 전 단계 통과"는 낡은 보고서를 읽은 것이며 실제로는 22시간 동안 완료된 CI 실행이 없었다.

## Decision

### D1. ADR-2026-09-04-C의 보류 해제·자기승인을 사후 추인한다
9/3 결정 기록의 "구현 보류"를 9/4에 대리가 스스로 해제했다. 명세 작성자(내부 감사)와 승인자(Chief Architect 대리)가
같은 역할이었다는 지적은 사실이다. 그러나 (a) 9/6 "모든 전권" 위임과 (b) 오늘 점검 보고를 읽은 뒤의 재위임이
그 판단을 소급 승인한다. 추인하되, **명세 작성자와 승인자가 같은 세션인 경우 ADR에 그 사실을 명기한다**는 규칙을 남긴다.

### D2. GitHub Actions는 2차 의견으로만 쓴다
결제 해제 직후 실측: push마다 `cancel-in-progress`가 직전 실행을 취소해 5연속 cancelled, 완주 0회.
워커 함대가 시간당 10건 이상 push하는 구조에서 push 트리거는 성립하지 않는다.
- 커밋 단위 검증은 로컬 CI(`pm/local_ci.py`, 게이트 16종)가 담당한다.
- Actions는 **3시간 주기 + 수동 실행 + PR**로만 돌린다. 독립 환경(ubuntu)에서의 재검증이 목적이다.
- `human_blocked.json` HB-4는 해소로 표기한다.

### D3. alembic head 분기는 기계적으로 막는다
이틀에 2회, 매번 DB 의존 풀 전체가 준비 단계에서 죽었다. 지침으로는 못 막았다.
- **1차 방어**: PM이 마이그레이션 리프를 한 사이클에 하나만 배정하고 나머지는 `depends_on`으로 직렬화한다.
- **2차 방어**: 메인 저장소 `.git/hooks/pre-push`가 `check_migration_chain.py`를 돌려 head 2개 push를 거부한다.
  훅은 모든 worktree에 공통 적용된다. 훅은 저장소 밖 로컬 인프라이므로 `pm/start_all.ps1`이 존재를 보장하지 않는다 —
  재설치 절차를 `pm/PM_HANDOFF.md`에 남긴다(후속).

### D4. 원장 테스트 픽스처는 분개를 거친다 (replay_verify 완화 안 함)
esc-2115: 픽스처가 `ledger_balance`에 raw 잔액을 심어 순수 재생이 음수 잔액으로 죽었다.
이벤트 소싱 불변조건(ADR-2026-09-06-B D3)이 테스트에서만 예외면 재현 보증이 거짓이 된다.
픽스처를 분개 경유로 바꾸고, raw 시드를 정적 검사로 금지한다(FA-15a).

### D5. 외부 교차검증(Codex/ChatGPT) 루프는 재개하지 않는다
브레인스토밍 → 외부 모델 교차검토 → 채택의 루프는 9/3 이후 실행되지 않았고, ADR-C가 채택 경로를 ADR 형식으로 재정의했다.
독립 검토는 함대의 reviewer 풀(별도 컨텍스트·별도 워크트리)과 적대적 QA가 담당한다. 외부 모델 교차검증이
필요하면 사용자가 별도로 지시한다. 브레인스토밍 레지스터와 `docs/research/brainstorm_2026-09-03/`는
**9/3 스냅샷으로 동결**하고 `INVARIANTS.md`를 정본으로 한다(동기화하지 않는다).

### D6. 로컬 CI는 조용히 죽지 않는다
`local_ci.py`의 준비 단계 예외가 22시간 동안 삼켜졌다. 예외도 실패 보고서로 발행해 `ci_red`와 에스컬레이션이
정상적으로 뜨게 했고, PM 지침에 `ci_stale` 처리(진단 task 생성)를 추가했다.

## Consequences
- 사람 결정 7건 중 6건 종결. 남은 1건(HB-1~3·5·6 계정·실자금·유료 데이터)은 원래 사람 몫이며 진행을 막지 않는다.
- Actions 분 소비가 시간당 수십 회에서 하루 8회로 준다.
- 마이그레이션 리프의 병렬도가 1로 떨어진다. 함대 정지 비용(회당 수 시간)보다 싸다.

## Rejected
- 대리의 9/4 자기승인을 무효화하고 EO-01~06을 되돌리기: P0 안전 결함 종결을 되돌리는 것이라 손해가 압도적이다.
- Actions를 push 트리거로 두고 cancel-in-progress만 끄기: 시간당 10회 × 20분 실행이 큐에 쌓여 분만 태운다.
- replay_verify 완화: 불변조건을 테스트가 우회하면 그 불변조건은 없는 것이다.
- 브레인스토밍 레지스터를 INVARIANTS에 맞춰 동기화: 정본이 둘이 되는 상태를 유지하는 비용이 크다. 동결이 맞다.
