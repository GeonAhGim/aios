# J8 모의 → 실전 전환 경로 구현 계획 (2026-11-06)

사용자 결정(2026-11-06): **전환 경로는 구현하되, MVP-1 종결 기준은 모의 운용까지**로 둔다.

## 범위

| 항목 | 결정 |
|---|---|
| MVP-1 종결 게이트 | 변경 없음(J1~J3, 모의 운용까지). J8은 종결 조건이 아니다. |

| 실전 주문 | **여전히 막혀 있다.** `Executor`의 하드 가드(mode != PAPER 차단, 보호 경로 `src/core/executor`)는 건드리지 않는다. 해제는 HB-5(별도 사용자 승인)다. |
| 자동 전환 | 금지. 모의 성과가 좋아도 사용자의 명시적 승인 없이는 전환되지 않는다. |
| 보호 경로 | `src/core/strategy·portfolio·risk·executor`는 이 계획의 어느 리프도 변경하지 않는다. 필요하면 FROZEN 승인 기록 task를 먼저 만든다. |

이미 있는 것: `POST /executions/{id}/convert-to-live`(PAPER → LIVE 새 실행), 실행 생성 감사 기록(`execution.created`, task-10779), LIVE 고액 배정 승인 요청(`approval.create_request`), 주문 2단계 확인 UI(task-10635), mandate 한도 게이트, 거래소 대조(reconcile), 감사·재현(replay).

## 전환에서 지켜야 할 것 -> 리프

| 원칙 | 현재 | 리프 |
|---|---|---|
| 전환 근거: 모의 성과 + 수수료·슬리피지·미체결·부분체결·장애 복구 | 성과표는 있으나 전환 흐름에 배선되지 않음 | **LP-1**(계산), **LP-2**(API) |
| 명시적 승인: 계좌·전략 버전·투입 자금·손실 한도 | 자금만 받음, 손실 한도·초기 노출 입력 없음, 재인증(step-up) 없음 | **LP-3** |
| 단계적 운용: 제한 노출로 시작, 확대는 별도 승인 | 없음 | **LP-4** |
| 사용자 화면: 모의/실전, 위험 노출액, 실행 중인 것, 멈추는 법 | 모드 드롭다운뿐, 상시 표시 없음 | **LP-5**(전환 화면), **LP-6**(상시 상태 띠) |
| 지속 통제·사후 추적 | reconcile·감사·replay 있음 | 변경 없음(전환 이벤트가 감사에 남는지만 LP-3에서 확인) |

## 리프 (모두 보호 경로 밖, 완료 기준에 테스트·린트·가드 포함)

- **LP-1 전환 근거 계산(순수 함수)**: PAPER 실행 하나의 체결·주문 행에서 기간, 체결 수, 순손익, 수수료 합, 평균 슬리피지, 미체결·부분체결 비율, 거부 건수, 장애 복구 이벤트를 계산. **자료가 없는 항목은 0이 아니라 `unavailable`로 명시**한다(없는 데이터를 좋은 성과로 보이게 하지 않는다).
- **LP-2 근거 조회 API**: `GET /executions/{id}/live-readiness` -> LP-1 결과. 본인 실행만, PAPER 실행만.
- **LP-3 전환 승인 입력 강화**(구현 963b21aa2, **경로 정정 fd8aae79c**): 필수 필드 추가는 v1 계약상 MAJOR라 OpenAPI 게이트가 막는다(107 §4). 기존 `convert-to-live`는 deprecated(410)로 두고 새 경로 `POST /executions/{id}/live-conversion`이 아래 요건을 받는다. 요청에 `max_loss_amount`(0 초과, 배정 자금 이하)와 `initial_exposure_pct`(1~100)를 필수로 받고, step-up 재인증을 요구하며, 값 전부를 `execution.converted_to_live` 감사 기록에 남긴다. 거부 사유는 구체적으로.
- **LP-4 단계적 노출**(구현 d03d0d6fb): 전환된 LIVE 실행은 목표 자본의 `initial_exposure_pct`%만 `allocated_capital`로 열고 시작한다. `POST /executions/{id}/expand-exposure`(재인증 필수)로만 확대하며 확대만 허용한다. 손실 한도 금액은 `max_drawdown_pct`로 환산해 기존 실행별 손실 가드가 강제한다. **정정(2026-11-07):** 처음 계획의 "mandate 한도로 표현"은 틀린 가정이었다 -- mandate는 포트폴리오 단위 정책이고 개정마다 쿨링오프·자기승인 금지 절차를 거치는 객체라 실행 하나의 단계적 노출에 맞지 않는다. 코어 변경 없음.
- **LP-5 전환 화면(프런트엔드, 구현 740fb9076)**: 실행 카드의 "실전 전환" -> LP-2 근거 요약, 실자금 사용 고지, 손실 한도·초기 노출 입력, 2단계 확인. 근거가 `unavailable`이면 그대로 보여 준다. 실전 주문이 하드 가드로 막혀 있는 동안에는 그 사실을 화면에 명시한다.
- **LP-6 상시 운용 상태 띠(프런트엔드, 구현 372a367e6)**: 대시보드·실행 화면 상단에 항상 보이는 띠 -- 모의/실전 배지, 위험 노출액, 실행 중 개수, "모두 멈춤" 1클릭.

## 하지 않는 것

- 하드 가드 해제, 실전 주문 활성화(HB-5).
- 모의 성과 기반 자동 전환, 자동 노출 확대.
- MVP-1 종결 게이트에 J8 추가(이번 결정으로 제외, 모의 운용까지가 종결).
