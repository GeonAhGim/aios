# ADR-2026-11-19-A: 종결 지표 재오픈은 같은 원인의 재발만 센다

## Status
Accepted (2026-11-19, 사용자 승인: "네"). ADR-2026-09-26-C §2(b)와 ADR-2026-11-18-A Decision 1 (b)의 집계 기준을 정밀화한다. 기준 값(3일 창, 재오픈 0)은 바꾸지 않는다.

## Context

지표 (b) "재오픈 0(3일 창)"은 `kind=ci_failure` 에스컬레이션의 `reopened_at`이 창 안에 있으면 센다. 에스컬레이션은 **CI 단계 이름**(`pytest`, `import_linter` 등) 단위 파일 하나라서, 같은 단계에 서로 무관한 원인의 새 적색이 생겨도 "해결됐던 것이 다시 깨졌다"로 센다.

2026-11-19 관측(3일 창 8건): 제 직접 푸시 누락(`perf_marker_guard`), 워커 커밋의 경계 위반(`import_linter`), 불안정 테스트(`pytest_perf`), 외부 취약점 공지(`npm_audit`) 등 원인이 제각각이었다. 새 적색마다 3일 시계가 처음부터 다시 시작돼 종결이 계속 밀린다. 한편 연속 녹색 3일(지표 (a))이 이미 "CI가 안정적인가"를 재고 있다.

## Decision

- 재오픈은 **같은 원인이 해결 뒤 다시 난 것**만 센다. 다른 원인의 새 적색은 재오픈이 아니라 새 실패이며 지표 (a)가 반영한다.
- 같은 원인 판정(`pm/closeout_reopen.py`): 해결 전 실패 출력과 재발 출력에서 테스트 node id·파일 경로를 뽑아 하나라도 겹치면 같은 원인. 경로가 없으면 숫자·해시를 지운 첫 줄을 비교한다. **근거가 없으면 같은 원인으로 센다**(보수적).
- 재오픈 시점에 `reopen_same_cause`를 기록한다. `False`인 건만 제외하고, 판정이 없는 기존 기록은 그대로 센다(소급 완화 없음).
- 같은 단계의 재검사가 계속 실패하거나 사람이 닫은 full 단계가 여전히 적색이면 같은 원인(`True`)으로 기록한다.
- 대시보드 ⑥은 제외한 건수("다른 원인 새 적색 N건은 ⑤가 반영")를 보여 준다. 숨기지 않는다.

## Consequences

- 서로 무관한 적색이 재오픈 시계를 되돌리지 않는다. 진짜 회귀(고친 것이 다시 깨짐)는 그대로 센다.
- 지표가 느슨해지지 않는다: 새 적색은 (a)에서 여전히 녹색 일수를 끊는다.
- 기존 8건은 판정이 없어 그대로 세므로 이번 창은 줄지 않는다(마지막 재오픈 2026-11-19 02:45Z 기준 11-22 창 종료). 효과는 이후 발생분부터다.
- 위험: 파일 경로가 겹치지 않는 같은 원인(드문 경우)을 새 원인으로 오판할 수 있다. 그 경우도 (a)가 녹색 일수로 잡는다.

## Rollback
`closeout_reopen.partition`에서 `SAME_CAUSE_KEY` 조건을 제거하면 이전 집계로 돌아간다.
