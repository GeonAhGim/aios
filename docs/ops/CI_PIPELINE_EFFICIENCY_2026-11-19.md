## 보류 항목의 이유와 조건

- **2. defer 해제**: 보류 사유는 벽시계 성능 단언이 부하에 흔들리는 것이다. python raw 타이머 단언 473건, frontend 단일 표본 134개 파일이 남아 있어(전환 리프 진행 중) 지금 해제하면 타이밍 적색이 늘 수 있다.
  해제 조건: frontend 단일 표본 baseline이 0 근접이고 python raw 타이머 baseline이 크게 줄며, 해제 뒤 24시간 full 타이밍 적색 0.
  더 작은 첫걸음: full의 heartbeat phase가 단계 이름이 아니라 python 경로(`processing:<python.exe>`)로 찍히는 단계가 있어 "타이밍 단계만 보류"로 좁힐 수 없다. 단계 이름을 항상 label로 넘기도록 고치면(소규모) 타이밍이 아닌 pytest 19분·frontend 4분 동안은 배치를 돌릴 수 있다.
- **3. full pytest 중복 제거**: 전체 pytest는 coverage 측정에 쓰이고, 배치 사전점검은 coverage·perf를 뺀 실행이라 결과가 같지 않다(`premerge_coverage` 주석). 단순 삭제는 coverage 래칫을 깬다. 먼저 coverage 수집을 분리할 수 있는지(커버리지 전용 가벼운 실행, 또는 배치 측정을 래칫과 맞춤) 측정한 뒤 정한다.
