# Pro Workspace 설계 (FE-9) — v0.1 초안

> 결정 기록: ADR-2026-11-18-B D3 FE-9. 상태: **초안(CTO 작성, 사용자 검토 대기)**. 구현은 MVP-1 종결 뒤 Phase 1.
> 표기: **[확인]** = 코드·문서로 확인한 사실, **[제안]** = 이 문서의 설계 제안, **[미확인]** = 아직 확인하지 못한 것.

## 1. 한 문장 비전

여러 거래소·여러 자산군을 **하나의 작업 공간**에서 다루되, 같은 종목·계정·시각을 모든 패널이 공유하고, 밀도는 사용자가 고르며, 위험한 행동에는 안전 규칙이 구조로 내장된 프로 트레이딩 워크스페이스.

"세상에 없던 것"은 개별 기능이 아니라 **네 가지의 결합**에서 나온다: (1) 맥락 공유 패널, (2) 거래소·자산군 정규화 뷰, (3) 밀도 단계가 있는 단일 구조, (4) 안전이 기본값인 복합 행동.

## 3. 작업 공간 모델 [제안]

```
Workspace  (사용자 소유, 서버 저장, 기기 간 동기화)
 ├─ Layout[]        이름 붙은 패널 배치(탭/분할/부유). 예: "스캘핑", "리서치", "점검"
 │   └─ Panel[]     종류(chart, orderbook, positions, orders, script, backtest, risk, news ...), 크기·위치, 패널별 설정
 ├─ Context         활성 맥락(아래 §4). 패널은 "맥락에 따름" 또는 "고정" 중 선택
 └─ Preset          밀도 단계·단축키·알림 규칙의 묶음
```

- 패널은 **페이지의 부분 화면이 아니라 독립 단위**다. 기존 페이지는 "패널 하나짜리 기본 레이아웃"으로 호환한다(점진 이행, 라우트 유지).
- 저장 단위는 레이아웃이다. 기존 차트 레이아웃 저장 API를 일반화하는 방향을 우선 검토한다 [미확인: 서버 API의 일반화 가능 범위].
- 패널 간 데이터는 **구독**으로만 흐른다(직접 참조 금지). 같은 데이터를 여러 패널이 열어도 요청은 한 번이다(캐시·스트림 공유).

## 4. 맥락 버스(Context Bus) [제안]

모든 패널이 공유하는 최소 맥락:

| 맥락 키 | 의미 | 예 |
|---|---|---|
| instrument | 정규화된 종목 식별자(거래소 중립) | "BTC/USDT 현물" 한 개념, 거래소별 심볼은 하위 |
| venue scope | 대상 거래소 집합 | 전체 / 특정 2곳 |
| account scope | 대상 계정·포트폴리오 | 모의 / 실계정A |
| time cursor | 기준 시각·구간(라이브 / 과거 시점) | 차트 십자선 시각 = 포지션 스냅샷 시각 |
| selection | 선택된 구간·주문·체결 | 차트에서 고른 구간 -> 백테스트 구간 |

규칙: (1) 맥락은 **명시적으로 보인다**(상단 맥락 바에 현재 값과 모드[모의/실전] 표시), (2) 패널은 맥락을 *읽기*만 하고 변경은 사용자 행동 또는 명시적 연결(link)로만, (3) **실전/모의 구분은 모든 패널에 항상 표시**하고, 모드가 섞인 패널 조합은 금지하거나 경고한다.

## 5. 다중 거래소·다중 자산군 정규화 [제안]

사용자에게는 하나의 개념으로 보이게, 내부에서는 차이를 숨기지 않는다.

| 차원 | 정규화 규칙 | 숨기면 안 되는 차이 |
|---|---|---|
| 종목 | 중립 instrument ID + 거래소별 심볼 매핑 | 거래소별 상장 여부·틱 크기·최소 수량 |
| 통화·단위 | 기준 통화로 환산한 뷰 + 원 통화 병기 | 환산 시각·환율 출처 |
| 시간 | 사용자 시간대 표시 + 거래소 세션 표기 | 휴장·세션별 거래 규칙, 서머타임 |
| 호가·체결 | 거래소별 호가를 한 뷰에 병합(출처 표시) | 지연·갱신 시각, 깊이 차이 |
| 주문 의미 | 사용자 의도(지정가/시장가/조건) -> 거래소별 변환 | **변환 불가·의미가 다른 경우는 명시적으로 거부 또는 경고** |
| 수수료·비용 | 예상 총비용 미리보기 | 수수료 체계·정산 통화 차이 |
| 자산군 | 현물·선물·주식 등 공통 포지션 뷰 + 자산군별 열 | 증거금·만기·배당 같은 고유 속성 |

원칙: **정규화는 편의이고, 불확실하거나 근사한 값에는 항상 근사 표시와 출처를 단다.** 정확하지 않은 통합 뷰는 없는 것보다 위험하다.

## 6. 밀도 단계 [제안]

같은 구조에서 설정으로 전환한다(별도 제품 아님).

| 단계 | 대상 | 특징 |
|---|---|---|
| L0 단순 | 처음 쓰는 사용자 | 패널 1~2개, 큰 글자·큰 목표, 설명 노출, 위험 행동은 단계별 안내 |
| L1 표준 | 일반 | 현재 페이지 중심 UI에 가까움, 패널 2~4개 |
| L2 프로 | 숙련 | 다패널 분할, 단축키·명령 중심, 인라인 편집 |
| L3 고밀도 | 전문 | 최소 여백·작은 글꼴·표 중심, 부유 패널·다중 모니터 |

공통 제약: 모든 단계에서 접근성(키보드, 대비, 확대) 기준(FE-5)과 성능 예산(FE-6)을 지킨다. 밀도는 시각 크기와 정보량을 바꿀 뿐 **안전 확인 절차를 줄이지 않는다.**

## 7. 명령 시스템 확장 [제안]

현재(내비게이션 전용)에서 확장:

1. 이동 명령(현행) -> 2. **맥락 명령**("종목 변경", "계정 전환", "레이아웃 불러오기") -> 3. **행동 명령**("이 구간 백테스트", "알림 만들기") -> 4. **복합 명령**(여러 거래소에 걸친 행동).
- 행동·복합 명령은 **실행 전 요약과 확인**을 거친다(MONEY_ACTIONS 규칙), 결과 불확실 시 완료로 표시하지 않는다.
- 자연어 입력(AI)은 4번과 같은 경로로만 실행한다 — 별도 우회 경로 금지.

## 7-A. 복합 행동의 안전 구조 [제안]

복합 주문·자동화일수록 구조로 막는다: (1) 위임장 범위 밖 행동은 UI에서 비활성+사유 표시, (2) 킬스위치·점검 상태는 모든 패널 상단에 공통 표시, (3) 다중 거래소 동시 행동은 **부분 성공 상태**를 일급으로 표시(일부만 체결 등), (4) 멱등키와 재시도 규칙을 한 곳에서 관리.

## 8. 성능·신뢰성 (밀도의 대가) [제안]

- 패널 N개가 같은 심볼을 구독해도 **스트림 1개**. 화면 밖·비활성 탭 패널은 갱신을 낮춘다.
- 목표(Phase 1에서 측정으로 확정): 8패널 구성에서 입력 지연(INP) ≤ 200ms, 차트 프레임 목표 달성, 메모리 상한 경고.
- 연결 끊김은 패널별이 아닌 **전역 상태 바**에 한 번 표시하고, 패널은 "낡은 데이터" 표지를 단다(DATA_FRESHNESS 규칙).

## 10. 시그니처 장면 후보 (사용자 선택 필요)

장면 하나를 정하면 그 장면이 가능한 최소 구조부터 거꾸로 설계한다.

- **A. 두 거래소 호가 비교 + 한 번 주문**: 호가 병합 패널, 최적 경로 제안, 주문 확인, 부분 체결 표시.
- **B. 차트 구간 -> 백테스트 -> 주문 초안**: 선택 구간이 백테스트로, 결과가 모의 주문 초안으로 이어지는 연속 흐름.
- **C. 다중 자산군 포트폴리오 점검판**: 현물·선물·주식을 통합 포지션·리스크 뷰로, 이상 징후 해설(AI) 포함.

## 11. 열린 질문

1. 시그니처 장면은 A/B/C 중 무엇을 우선할까 (혹은 다른 장면)?
2. 1차 지역·언어(ko/en 우선인지), 1차 자산군(가상자산 우선인지)?
3. 다중 모니터·부유 패널은 Phase 1 범위인가, Phase 2인가?
4. 모바일은 별도 설계(FD-21)로 둘 것인가, 같은 작업 공간 모델의 축소판으로 갈 것인가?

## 12. 갭 조사 항목 (Phase 0에서 확인)

- 종목 정규화(거래소 중립 ID) 구현 범위, 거래소 간 호가 병합 가능성(어댑터 WS 지원 현황).
- 레이아웃 저장 API의 일반화 가능 범위.
- 현재 페이지들의 패널화 난이도(전역 상태·라우트 의존).
- 데이터 라이선스상 한 화면 병합·재가공 제약.
