# 화면 기능 명세 템플릿 (FE-1)

> 정본 위치: `docs/frontend/screens/<여정>-<화면>.md`. 이 템플릿의 **모든 절을 채운다**(해당 없으면 "해당 없음 + 이유").
> 기준: ADR-2026-11-18-B. 명세와 구현이 어긋나면 명세가 기준이고, 어긋남은 §12 갭 표에 적는다.
> 사실은 코드·API 스키마·실스택 관찰로 확인한 것만 적는다. 확인하지 못한 것은 "미확인"으로 표시한다(추측 금지).

## 1. 개요

- **화면 이름 / 라우트 / 소스 파일**:
- **여정 소속**(J1~J6)과 단계 번호:
- **목적**(한 문장, 사용자 관점):
- **페르소나**(누가 언제 이 화면에 오는가 — 예: 첫 방문자, MFA 미등록 사용자, 관리자):
- **진입 조건**(로그인·MFA·위험성향·플래그·권한):
- **사용자 준비물**(예: 인증 앱, 거래소 키) — 화면에 오기 전 사용자가 알아야 하는 것:

## 5. 금전·위험 행동 규칙 (해당 시)

- 확인 절차(2단계 확인, 요약 표시), 멱등성(재제출·새로고침·중복 클릭), 불확실 상태(타임아웃 후 결과 불명)의 표시.
- **불확실한 결과를 "완료"로 표시하지 않는다**(fail-closed). 규칙 근거는 XCUT 금전 행위 절.

## 6. 오류 문구와 복구 안내

| 오류 범주 | 사용자 문구(i18n 키) | 다음 행동 안내 | 개발자용 정보(trace_id 노출 여부) |
|---|---|---|---|

## 7. 접근성 (WCAG 2.2 AA)

- 키보드 순서·포커스 이동, 오류 알림 방식(role=alert/aria-live), 라벨·이름, 색 비의존 표현, 모션.

## 8. i18n / 지역화

- 가시 문자열 키 목록 위치, 숫자·통화·날짜·시간대 처리(단일 유틸 경유 여부), 복수형, 지역별 고지.

## 9. 성능 예산

- 목표(LCP/INP, 요청 수, 폴링 비용)와 실측(있으면). 무거운 렌더(차트·긴 목록)의 처리 방식.

## 10. 텔레메트리·관측

- 기록하는 이벤트, 오류 리포팅 시 포함하는 trace_id, 개인정보 제외 규칙.

## 11. 수용 기준 (테스트로 검증 가능한 문장)

- [ ] (실스택 e2e) …
- [ ] (단위/컴포넌트) …
- 각 항목에 검증 수단(어느 테스트 파일)을 적는다. 없으면 "없음 -> 리프 필요".

## 12. 구현 대비 갭 표

| # | 명세(기대) | 현재 구현(관찰·근거: 파일:줄 또는 실스택 재현) | 심각도(차단/중요/개선) | 처리(리프 번호 또는 "Phase 1") |
|---|---|---|---|---|

## 13. 미규정 액션 후보

- 명세에 없던 동작을 발견하면 `docs/frontend/UNSPECIFIED_ACTIONS.md`에 옮겨 적고 여기에 번호를 링크한다.
